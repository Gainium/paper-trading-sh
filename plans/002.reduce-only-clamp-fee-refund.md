# 002 — reduceOnly clamp refunds the wrong fee

Plan for [`specs/002.reduce-only-clamp-fee-refund.md`](../specs/002.reduce-only-clamp-fee-refund.md).

## Solution

Rewrite the refund at the head of the `diff <= 0 && order.reduceOnly` branch in
`src/order/order.service.ts` so the clamped-off units are priced with the same
conversion the fill used, factoring `feePerc` out of the ternary:

```ts
order.fee -=
  (isCoinm(order.exchange)
    ? (Math.abs(diff) * symbol.quoteAsset.minAmount) / order.price
    : Math.abs(diff) * order.price) * feePerc
```

That is the shape the non-reduceOnly sibling branch immediately below already
uses to recompute the fee for the units it closes — the two branches now read
the same, which is the point.

This is the root cause the spec's Assumption names, not a symptom: no clamp is
applied to `order.fee` afterwards, no compensating error elsewhere is being
cancelled out. The rest of the branch is untouched.

## Why no extraction

JIT tier **0/1 boundary → stay at 0**. The formula is written inline in five
places in this file, so there is a real case for lifting it into `src/order/fees.ts`
(this repo's existing home for paper fee rules). Rejected for this change:
rewiring the four *correct* call sites is churn on code that is not on the
causal path, and the fix is verifiable without it — the test drives the real
`processFuturesPosition`, so it pins the call site's behaviour, which a test of
an extracted helper would not. Worth doing as its own task; noted here, not
smuggled into a bug fix.

No new helper is added: nothing new is being computed, and `fees.ts`'s
`paperOrderFee` reports a fee rather than deriving one, so it does not fit.

## Blast radius

1. **Other call sites.** The changed expression is a single statement inside one
   private branch; it is not a function, so there are no other callers. `grep`
   for the pattern finds no copy elsewhere. The four other places that compute a
   futures fee (`createOrder` market path ×2, resting-order fill loop ×2, the
   non-reduceOnly flip branch) are *unchanged* — this change makes the branch
   agree with them.
2. **`core/` submodule.** Yes: this file is `paper-trading-sh`, shared with the
   self-hosted build. The parent pointer must be bumped at ship time. The change
   is arithmetic inside one branch — no exported signature, no schema, no config.
3. **Contracts this repo owns** (per `CLAUDE.md`): the mirrored REST surface /
   `BaseReturn<T>` and the socket.io events are untouched. `order.fee` is
   *reported* to main-app through `paperOrderFee` (`feePaid`/`feeSide`), so the
   value main-app books changes — that is the fix, and it moves toward the live
   connectors' behaviour, not away from it. Note `paperOrderFee` already drops a
   negative fee rather than reporting it, so today's negative-fee orders reach
   main-app as "no fee observed"; after this change they report a real fee.
   No field is added or removed.
4. **Other tests on this path.** `src/order/fees.spec.ts` (10 cases) must stay
   green; it exercises `paperOrderFee`, which reads `order.fee`.
