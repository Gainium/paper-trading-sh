# 006 — dependency security floors

Bug spec.

## 1. Definition

### 1.1 Expected

Every copy of a package that `package-lock.json` resolves (the tree `npm ci`
installs) is at or above the first release that fixes its published security
advisory:

| package | floor | advisory class |
|---|---|---|
| body-parser | 2.4.0 | crash on trailing bytes after a compressed body |
| multer | 2.5.0 | upload handling DoS |
| fast-uri | 3.1.9 | URI parsing issue |

### 1.2 Unchanged

Runtime behaviour of paper-trading. Every bump is a patch/minor inside the
already-declared semver ranges; no API is used differently.

## 2. Evidence

Before the change the lockfile resolves body-parser 2.3.0, multer 2.4.0 and
fast-uri 3.1.8 — all below their floor.

## 3. Assumption

An in-range `npm update` of the three packages is enough; no `overrides`
entry is needed unless a nested copy stays below the floor.

## Invariants

None — this is a lockfile property, enforced by `src/dependencyFloors.spec.ts`
in `npm test`, not prod data state.
