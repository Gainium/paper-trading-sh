## Blast Radius

- Callers of `processFuturesPosition`: `processLimitOrder` (limit fills),
  `processMarketOrder` (market orders, incl. liquidations via
  `closeFuturePosition` → `createOrder`). All now queue per user + symbol.
- Deadlock check: inside the function only `lockLeverage` / `unLockLeverage`
  (`commonMutex`, not awaited) and model/wallet calls run; nothing re-enters
  `processFuturesPosition`. `closeFuturePosition` holds `commonMutex` on the
  position uuid and then takes this mutex — a fixed order, no cycle.
- Cost: a user's fills on one symbol are processed one at a time instead of
  interleaved; other users and symbols are unaffected.
- `core/` submodule: shared by the paper-trading service only; no REST,
  socket or schema shape changes.
- Other tests: `reduce-only-clamp.spec.ts` drives the same function and stays green.
