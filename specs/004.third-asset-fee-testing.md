# 004 — report a symbol's fee as paid in a configurable third asset

Feature spec. Replaces the unspecced `PAPER_ZERO_FEE_SYMBOLS` env var
(added ad hoc, never shipped/committed) with a different testing tool
for the same underlying need.

## Context

Testing on paper needs a way to exercise "the venue's fee doesn't come
out of base/quote" without a real BNB/BGB/KCS-discount exchange
account. `PAPER_ZERO_FEE_SYMBOLS` tried this by forcing the account
rate to 0% for a symbol — but that turned out to test the wrong thing:

- A confirmed-zero fee has nowhere to land in the observed-fee
  contract. `hasObservedFee`/`observedFeeSplit` (app,
  `src/bot/orderFee.ts`) both gate on `amount > 0` — `feePaid: '0'` is
  indistinguishable from absent, by design (`fees.ts`'s own docstring:
  absent, never a zero claim). Reporting one wouldn't change anything.
- Even if it did: `getTPOrder`'s quantity gross-up (app,
  `dcaHelper.ts:13994-14001`) never reads a fee AMOUNT for sizing — it
  applies the flat account-rate estimate unless
  `tpQuantityFeeIsThirdAssetOnly` gates it off entirely. There is no
  code path that would size a gross-up from a literal observed fee
  value, zero or otherwise.

So testing "zero on-pair cost ⇒ no TP offset" needs the SAME gate real
zero-cost trading already produces: a fee that is real, observed, and
entirely OFF the pair — which `quantityFeeIsThirdAssetOnly` /
`ordersFeeIsThirdAssetOnly` (app, `dca/tpFees.ts` — spec 014/015)
already handle correctly and skip the gross-up for. Simulating a
third-asset fee exercises that exact, already-tested path instead of
requiring a new one.

## Behaviour

For a symbol named in a new env var, paper-trading reports the fee it
already charges as paid in a configurable off-pair asset (default
ticker `GNM`) instead of splitting it onto `feeSide: base | quote`.
The **amount charged and the wallet impact are unchanged** — this is a
reporting-only override. Nothing about the simulator's own accounting
changes; only what gets told to the consumer about which asset the fee
came out of changes, the same way a real BNB-discount account's `fee`
number is unaffected by which asset happened to cover it.

- `PAPER_FEE_ASSET_SYMBOLS` — comma-separated, exchange-agnostic
  symbols (matches `order.symbol`), same shape as the env var this
  replaces.
- `PAPER_FEE_ASSET` — the ticker to report. Optional; defaults to
  `GNM` when `PAPER_FEE_ASSET_SYMBOLS` is set and this is not.

A listed symbol's filled order reports `feePaid` (the real charged
amount, string) + `feeAsset` (the configured ticker) — never
`feeSide`, mirroring how a real venue reports one or the other, never
both (`CommonOrder.feeAsset`'s own doc: "When set, `feeSide` is
absent").

An unlisted symbol is unaffected — same `feeSide` behavior as today.

A `fee <= 0` order (nothing charged) still reports nothing at all,
listed symbol or not — the "absent, never a zero claim" rule is
unchanged by this feature; it governs a different question (was
anything charged) than this one (which asset, given something was).

## Open questions

- Should `PAPER_FEE_ASSET` be global or itself per-symbol (e.g. a
  different fake ticker for different test symbols)? Proposed: global
  for now — nothing in the stated testing need requires more than one
  fake ticker at a time, and a single env var is simplest to reason
  about. Revisit if a concrete case needs two.
- Futures: `paperOrderFee` already picks `feeSide` deterministically
  per venue type for a normal report (inverse→base, linear→quote).
  This override should apply identically regardless of venue
  type/futures-vs-spot — the point is testing the THIRD-ASSET path,
  which `dca/tpFees.ts`'s `ordersFeeIsThirdAssetOnly` treats the same
  way for both. No special-casing needed; confirm in gate 2.
