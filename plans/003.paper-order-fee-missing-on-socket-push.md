# 003 — paper order's socket push never carries the observed fee

Plan for [`specs/003.paper-order-fee-missing-on-socket-push.md`](../specs/003.paper-order-fee-missing-on-socket-push.md).

This bug spans three repos (paper-trading → websocket-connector →
app), all sharing one contract: the order payload that leaves this
service's socket.io `order` event. Both gaps named in the spec's
Assumption (A: root cause here, B: two consequential drops downstream)
must land together — A alone never reaches main-app; B alone has
nothing to forward.

## Solution

### A — paper-trading (this repo, root cause)

Centralize the fix at `UserGateway.sendOrderToClient`
(`src/ws/user.gateway.ts:69-77`) rather than at each of the 5 push call
sites: every one of them already passes an `OrderDataType`-shaped
object, and `OrderDataType` already carries the three fields
`paperOrderFee` needs (`fee`, `exchange`, `side` —
`src/schema/order.schema.ts:80-96`). One call, at the one place that
owns "shape the order for the wire":

```ts
async sendOrderToClient(userId: string, data: OrderDataType) {
  const clientIds = this.orderClientUsersMap.get(userId)
  if (!clientIds || clientIds.size === 0) {
    return
  }
  this.server
    .to(Array.from(clientIds))
    .emit('order', { type: 'update', data: { ...data, ...paperOrderFee(data) } })
}
```

This is the root cause the spec's Assumption (A) names: no call site
computes the fee for the socket push at all, so fixing the one place
all five already funnel through closes it for good, including any
future call site — the exact way this bug was introduced in 1.3.8 (the
REST paths were updated, the push path wasn't, because it wasn't a
single shared place).

`data`'s declared type gains nothing new — `paperOrderFee`'s return is
spread into the *emitted* object only, not persisted back onto `data`,
so `OrderDataType` itself is untouched.

### B — websocket-connector (consequence, `core/` submodule)

`PaperOrderMessage` (`core/src/userStream.ts:422-437`) gains:

```ts
feePaid?: string
feeSide?: 'base' | 'quote'
```

`preparePaperOrderMsg` (`:4181-4201`) copies them onto the
`ExecutionReport` it returns, following the same "present it if present, else
omit" rule the rest of that function already follows implicitly (every
field it sets comes straight from `msg`):

```ts
...(msg.feePaid !== undefined ? { feePaid: msg.feePaid } : {}),
...(msg.feeSide !== undefined ? { feeSide: msg.feeSide } : {}),
```

`ExecutionReport`'s `SpotUpdate` variant does not declare `feeSide`
today (app repo, see B2) — this repo's own `ExecutionReport` type
(wherever it's declared here, mirroring app's) needs the same field
added or the value has nowhere typed to land. Confirm at implementation
time whether this repo keeps its own copy of that type or imports
app's; add `feeSide?: 'base' | 'quote'` alongside the existing
`feePaid`/`feeAsset` there.

### B2 — app (consequence)

- `app/core/types.ts` `SpotUpdate` gains `feeSide?: 'base' | 'quote'`
  next to the existing `feePaid`/`feeAsset`/`feeBreakdown`/
  `feePaidUsd`.
- `app/core/src/bot/main.ts:5263-5274`
  (`convertExecutionReportToOrder`) gains the same present-if-present
  copy the existing `feeAsset` block uses:

  ```ts
  if ('feeSide' in msg && msg.feeSide !== undefined) {
    order.feeSide = msg.feeSide
  }
  ```

  placed with the other three (`feePaid`/`feeAsset`/`feeBreakdown`),
  not replacing any of them — a real venue may still report `feeAsset`
  instead, and that path must keep working unchanged.

## Why no extraction

JIT tier **0** everywhere this change lands. `paperOrderFee` is already
the pure decision function this repo uses for "what fee shape do we
report" (Part 3's pure-decision-module role) — this change is one new
*call* to it from an existing adapter (`UserGateway`, already I/O by
nature: sockets), not new decision logic. B/B2 are field additions to
two existing wire types plus two existing present-if-present copy
blocks, each following a pattern already established in the same
function for a sibling field (`feeAsset` in both cases) — there is
nothing here shaped like decision-logic-mixed-with-I/O to pull apart.

## Blast radius

1. **Other call sites.**
   - This repo: all 5 `sendOrderToClient` call sites
     (`order.service.ts:794,1253,1720,1907,1982`) are fixed by the one
     change in A — grepped, no other caller of `sendOrderToClient`
     exists.
   - websocket-connector: `preparePaperOrderMsg` has one call site
     (`:3599`) — grepped, confirmed.
   - app: `convertExecutionReportToOrder` has two call sites
     (`main.ts:4633,5777`) — both benefit from B2, neither needs
     changing itself.
2. **`core/` submodule.** All three repos edit inside their `core/`
   submodule (`paper-trading-sh`, `websocket-connector-sh`,
   `main-app-sh`) — shared/deployed platform-wide. Each parent pointer
   needs bumping deliberately at ship time, and the three should ship
   together: B alone forwards fields that don't exist yet (harmless —
   `undefined` on `msg`, so the spread is a no-op); A alone computes
   fields nothing forwards (harmless — extra keys on a payload nothing
   downstream reads yet). Neither half regresses anything shipped
   alone, so the three can merge in any order, but the bug isn't closed
   until all three are live.
3. **Contracts owned, per each repo's own `CLAUDE.md`.**
   - paper-trading: "socket.io events … `websocket-connector` bridges
     these — renaming breaks simulated fills reaching the stream."
     This change adds two optional keys to `data`, does not rename or
     remove anything — non-breaking by that document's own standard.
   - websocket-connector: `core/src/utils/paperTradingWS.ts` (`PAPER_WS`
     bridge) is unaffected — it forwards whatever `PaperOrderMessage` it
     receives structurally; only the type gains fields and
     `preparePaperOrderMsg` reads two more of them.
   - app: `ExecutionReport`/`SpotUpdate` is not listed in this repo's
     "OWNS/EMITS" (main-app is the *consumer* on this path, not the
     owner) — adding an optional field to a type it reads is not
     touching anything main-app itself emits (GraphQL/REST/socket.io
     :7502/Rabbit).
4. **Other tests on this path.**
   - paper-trading: `src/order/fees.spec.ts` (13 cases, including the
     `isZeroFeeSymbol` tests from the prior task) exercises
     `paperOrderFee` directly — untouched by A, must stay green.
   - No existing test in any of the three repos currently exercises
     `sendOrderToClient`, `preparePaperOrderMsg`, or
     `convertExecutionReportToOrder`'s fee-copy block — gate 2 adds the
     first ones for each.
