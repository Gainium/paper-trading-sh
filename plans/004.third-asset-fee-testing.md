# 004 — report a symbol's fee as paid in a configurable third asset

Plan for [`specs/004.third-asset-fee-testing.md`](../specs/004.third-asset-fee-testing.md).

## Solution

### Remove `PAPER_ZERO_FEE_SYMBOLS`

Delete `isZeroFeeSymbol` from `fees.ts`, the `symbol` param from
`getUserFee` (`order.service.ts`) and its 5 call sites (revert to the
2-arg call), and the `isZeroFeeSymbol` describe block in
`fees.spec.ts`. It was never committed, never specced, and per spec
004's Context section doesn't test what it was meant to.

### Add the third-asset override

`paperOrderFee`'s parameter type already gets `symbol: string` — every
call site already passes an object with `.symbol` on it
(`OrderDataType`/`OrderDocument`), so no call site needs to change:

```ts
// fees.ts
export function isThirdAssetFeeSymbol(symbol: string): boolean {
  const list = process.env.PAPER_FEE_ASSET_SYMBOLS
  if (!list) return false
  const target = `${symbol ?? ''}`.toUpperCase()
  return list.split(',').map((s) => s.trim().toUpperCase()).filter(Boolean).includes(target)
}

export function thirdAssetFeeTicker(): string {
  return (process.env.PAPER_FEE_ASSET || 'GNM').trim().toUpperCase()
}

export function paperOrderFee(order: {
  fee?: number
  exchange: ExchangeEnum
  side: OrderSide
  symbol: string
}): { feePaid?: string; feeSide?: 'base' | 'quote'; feeAsset?: string } {
  const fee = Number(order?.fee)
  if (!Number.isFinite(fee) || fee <= 0) {
    return {}
  }
  if (isThirdAssetFeeSymbol(order.symbol)) {
    return { feePaid: `${fee}`, feeAsset: thirdAssetFeeTicker() }
  }
  const feeSide: 'base' | 'quote' = isFutures(order.exchange)
    ? isCoinm(order.exchange) ? 'base' : 'quote'
    : order.side === 'BUY' ? 'base' : 'quote'
  return { feePaid: `${fee}`, feeSide }
}
```

The `fee <= 0` guard stays first and unchanged — spec 004's "absent
≠ zero" carve-out.

## Why no extraction

JIT tier **0**. This is the same pure function the prior (unspecced)
feature already lived in, gaining one more branch on data it already
receives (`symbol` was already implicitly available via `order`, just
not in the type). No new I/O, no new coupling.

## Blast radius

1. **Other call sites.** `paperOrderFee`'s 6 call sites (5 in
   `order.service.ts`, 1 in `user.gateway.ts`, spec 003) are
   unaffected — same call shape, wider accepted type. `getUserFee`'s
   revert touches its 5 call sites (all within `order.service.ts`,
   already grepped for spec 004's removal step).
2. **`core/` submodule.** `paper-trading-sh`, shared/deployed
   platform-wide — parent pointer bump needed at ship time, alongside
   the `.env.sample` changes (both the outer and `core/` copies).
3. **Contracts this repo owns.** The mirrored REST surface gains
   `feeAsset` as a possible field on `CommonOrder` for paper orders —
   already a declared, real field on that contract (real venues set it
   today); this is the first time paper does. Companion change needed
   in `websocket-connector-sh` (separate spec) to forward it over the
   socket bridge the same way spec 003 did for `feePaid`/`feeSide` —
   `PaperOrderMessage`/`preparePaperOrderMsg` don't carry `feeAsset`
   yet. App needs no change: `feeAsset` has been a handled field there
   since before this session (real-venue path).
4. **Other tests.** `fees.spec.ts`'s existing `paperOrderFee` cases (10)
   must stay green — the new branch only fires when
   `PAPER_FEE_ASSET_SYMBOLS` names the order's symbol, which none of
   those cases do.
