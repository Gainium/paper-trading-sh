# 003 — paper order's socket push never carries the observed fee

Bug spec.

## 1. Definition

`paperOrderFee()` (`src/order/fees.ts`, shipped in 1.3.8) computes
`feePaid`/`feeSide` for a filled paper order, in the shape the real
connectors report theirs. `CLAUDE.md` documents this service's
socket.io `order` event as a contract pair with `exchange-connector`'s
user-stream forwarding — `websocket-connector` bridges it into
main-app's live order-update stream, the same path a real exchange's
`executionReport`/`ORDER_TRADE_UPDATE` arrives on.

### 1.1 Expected

A filled paper order's `feePaid`/`feeSide` reach main-app on **both**
paths a real exchange's fee does: the REST order lookup, and the live
socket.io push that drives immediate TP placement. main-app's
`observedFeeSplit` (`app`'s `src/bot/orderFee.ts`) does not
distinguish where an order came from — it reads whatever `feePaid`/
`feeSide`/`feeAsset` is on the order it was handed. For the two paths
to agree, both must carry the same fee fields.

### 1.2 Actual

`paperOrderFee()` is only ever spread onto the object this service
returns from its REST endpoints. Every place this service pushes an
order over `UserGateway.sendOrderToClient` — the thing `websocket-connector`
subscribes to and rebroadcasts — omits it:

- `src/order/order.service.ts:794` — `{ ...order.toObject(), id: ... }`
  (cancel/reject path)
- `:1253`, `:1720` — `mapOrderDocumentToDataType(orderInDb)`
- `:1907`, `:1982` — the raw in-memory `order` object (resting-order
  fill loop, both SELL and BUY arms)

`mapOrderDocumentToDataType` (`:847`) copies `fee`/`feePerc` — the
service's own internal numbers — but never calls `paperOrderFee()`.
`order.toObject()` and the raw `order` object are Mongoose
documents/DTOs against `OrderDataType`/`OrderDocument`
(`src/schema/order.schema.ts:41,44,88,89`), which likewise only
declares `fee`/`feePerc` — `feePaid`/`feeSide` are not schema fields
and were never intended to be persisted; they are REST-response-only,
computed fresh at each of the 5 `paperOrderFee(...)` call sites
(`order.service.ts:421,447,513,549,574`).

So a filled paper order's fee reaches main-app on the REST path, but
not on the live-stream path — the one `onFilled`/TP placement actually
runs on.

## 2. Evidence

Traced code path, read directly (no live repro run in this session):

1. `paper-trading/core/src/order/order.service.ts` — grepped every
   `sendOrderToClient` call site (5) and every `paperOrderFee` call
   site (5, listed above); confirmed by reading each that they are
   disjoint — no push site's payload passes through `paperOrderFee`.
2. `paper-trading/core/src/schema/order.schema.ts:41,44,88,89` —
   `OrderDataType`/`OrderDocument` declare `fee`/`feePerc` only.
3. `websocket-connector/core/src/userStream.ts:422-437` —
   `PaperOrderMessage` (the type of what arrives over the paper
   gateway subscription) declares no `feePaid`/`feeSide`/`feeAsset`
   field at all — consistent with §1's payload never having carried
   one.
4. `websocket-connector/core/src/userStream.ts:4181-4201` —
   `preparePaperOrderMsg` builds the `ExecutionReport` it forwards to
   main-app as an explicit field list; it does not reference
   `feePaid`/`feeSide` (there is nothing on `msg` to reference).
5. `app/core/types.ts` (`SpotUpdate`) — the wire type for
   `ExecutionReport` declares `feePaid`/`feeAsset`/`feeBreakdown`/
   `feePaidUsd`, but **not** `feeSide` — the one field paper ever sets
   (it never sets `feeAsset`).
6. `app/core/src/bot/main.ts:5263-5274`
   (`convertExecutionReportToOrder`) copies `feePaid`/`feeAsset`/
   `feeBreakdown`/`feePaidUsd` from the incoming stream message onto
   the order — never `feeSide`. A second, independent omission: even
   if paper-trading started putting `feeSide` on the socket payload
   tomorrow, this merge would still drop it.
7. By contrast, `app/core/src/bot/main.ts:5278-5333`
   (`mergeCommonOrderWithOrder`, the REST-poll merge) uses
   `observedFeeOf(...)` (`src/bot/orderFee.ts:70-82`), which does copy
   `feeSide` — confirming the REST path is fine and the gap is
   specific to the live-stream path.

## 3. Assumption (hypothesis)

Two independent gaps on the live-stream path, both required to fix it
end to end:

- **A. paper-trading (root cause).** The socket.io `order` push was
  never updated when `paperOrderFee()` was added in 1.3.8 — it was
  wired into the REST response shape only. Fixing this means every
  `sendOrderToClient` call site sends an object carrying
  `paperOrderFee(order)`'s output, not just `fee`/`feePerc`.
- **B. websocket-connector + main-app (consequence).** Even with A
  fixed, `PaperOrderMessage`'s type and `preparePaperOrderMsg` need
  `feePaid`/`feeSide` added to forward them, and main-app's
  `convertExecutionReportToOrder` needs to copy `feeSide` (not just
  `feePaid`/`feeAsset`) — otherwise A's fix is silently dropped one or
  two hops downstream, with no error anywhere.

Fixing only A would leave the bug fully in place. Fixing only B has
nothing to forward.

## 4. Out of scope

- `feeAsset`/`feeBreakdown`/`feePaidUsd` on the paper path — paper
  never sets these (`paperOrderFee` only ever returns `feePaid`+
  `feeSide`, per its own docstring), so there is nothing to thread
  through for them here.
- Whether main-app's TP sizing *actually* falls back to the estimate
  in practice today because of this — plausible from the trace, not
  separately reproduced live. If gate 5's fix doesn't change observed
  paper-testing behavior, that's a sign this Assumption needs revising
  before closing the bug, not a reason to skip verifying against a real
  paper fill after the fix ships.
